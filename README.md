# 地牢刷数值 · 广告游戏 Demo

复刻 Google Play 上那类「掉进地牢、头顶数字、点击刷战力」的广告小游戏。
**纯前端、零依赖、零构建**——直接双击 `index.html` 就能玩。

## 核心机制（和原版一致）

这不是砍血条的游戏，**战力就是一切**：

| 情况 | 结果 |
|---|---|
| 战力 **≥** 怪物 | 一击秒杀，并把怪物的战力**吞**进来（数字膨胀） |
| 战力 **<** 怪物 | 被它击杀，**立即失败** |

所以全部策略就是：**走位选择**——先挑小的刷到膨胀，再回头碾压刚才打不过的。
怪物基本不动，由主角移动去"选"目标；会追人的怪和隐藏陷坑作为额外机制。

## 操作

- **点击地面**移动（自动寻路绕墙），也支持 **WASD / 方向键**
- **撞上**怪物就是攻击，撞上 ⚔ 装备 / 🎁 道具即拾取
- 红色数字 + 脉冲红圈 = 现在打不过，绕着走
- 清空本层全部怪物进入下一层，每 5 层一个 BOSS

## 道具

🛡 无敌护盾 5 秒 · 💥 炸弹（消灭周围所有打得过的怪）· 🧲 磁铁（吸取附近装备道具）
👟 疾风之靴 6 秒 · 🍀 幸运四叶草 10 秒内吞噬翻倍

## 变现点（全部为模拟演示）

这些按钮就是这类游戏真实的商业化设计，本 demo 用一个**假广告弹窗**（带 5 秒倒计时和
点不动的"假关闭按钮"）来演示套路，**不会加载任何真实广告、不会扣费**：

- 💀 死亡 → 看广告复活（无敌 4 秒 + 战力 ×2 20 秒）
- ▶ 看广告抽装备（战力 +50%~100%）
- ▶ 看广告解锁自动战斗 60 秒
- 👑 首充 ¥6：战力 ×3 + 永久自动战斗

## 运行

```bash

start index.html          # Windows

# 方式二：本地服务器（推荐，避免某些浏览器的 file:// 限制）

```

## 代码结构

```
index.html      页面结构（HUD / 侧面板 / 各类弹窗）
style.css       样式（暗色地牢主题，响应式）
balance.js      纯数值模块：怪物倍率、成长曲线、道具池、万/亿格式化
engine.js       纯逻辑引擎：无 DOM 依赖，可在 Node 里跑模拟
render.js       Canvas 2D 俯视渲染：地牢、怪物、飘字、粒子、火光
ui.js           DOM/HUD/输入/广告模拟/音效
main.js         入口
test/           测试
```

**分层的目的**：`balance.js` 和 `engine.js` 不碰 DOM，所以能在 Node 里注入随机数
跑几万帧的机器人模拟，直接验证数值曲线——而不是靠手感想"大概不难吧"。

## 数值设计要点

几个用测试固化的关键约束：

1. **可清空性不变量（链式）**——把每层怪物按倍数升序排列，第 i 只怪的倍数不允许超过
   `1 + absorbRatio × Σ(前面怪的倍数)`，也就是「刷完前面这些之后能达到的战力」。
   这保证无论数值多夸张，玩家永远能一层层滚上去，不会出现
   「小的刷完、大的永远打不过」的死局。
2. **每层保底有怪可刷**——至少 `monsterMinBeat` 只怪落在低倍率区间，
   否则深层层一进门全是打不过的，直接卡死。
3. **普通怪倍数区间随层数整体上移**——只让精英/BOSS 变强是不够的，
   深层层连普通怪也得追上玩家的相对强度，否则玩家一路秒过去毫无压力。
   `lo` 必须封顶（`normalMulLoMax`），否则深层层没有能刷的怪（这个 bug 真实踩过）。
4. **吞噬比例 < 1**——全吞时每层成长 = `1 + Σ倍数`，层数一多就指数爆炸，
   敌人的相对强度永远追不上玩家，这就是「战力膨胀太快」的根源。
5. **起始战力不能是 1**——怪物战力 = 起始战力 × 倍数，倍率下限只有 0.25，
   全都会 round 到 1，第一个房间就是一排「1」，毫无成长感。
6. **追击怪速度慢于主角**——危险但跑得掉。

## 已知边界

- 没有存档续杯（刷新即重开），只有 `localStorage` 记录最高层数
- 自动战斗是简单的"找最近的能打的怪"，不会规划路线
- 音效是 WebAudio 现场合成的方波，没有素材
